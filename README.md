# 1on1目標・タスク管理アプリ

**会話を止めずに目標を整理する。**

1on1を実施しながら、目標・タスク・進捗を管理するWebアプリです。
Codexを活用して、要件整理から実装・テスト・公開まで進めました。

- [公開アプリ](https://task-management-api.renaito008.workers.dev/)
- [GitHubリポジトリ](https://github.com/renaito008/aitask2026)

現在はデプロイまで完了し、使い勝手の改善を続けています。

## 1. システム概要

本人は目標やタスクを更新し、相手は閲覧リンクから確認します。

- 目標(3件まで)・タスク(3件まで)・進捗の管理
- 1on1ごとの備考と、過去3回の履歴
- 編集リンクと閲覧リンクによる共有

## 2. アイデア出し・要件定義

AIとの対話で利用場面を整理し、必要な機能と追加しない機能を決めました。

**重視したこと：操作を増やさない・取り組みを絞る・振り返りを残す**

## 3. 設計

画面・業務ルール・保存処理を分離しました。
ローカル試作から始め、段階的にサーバー保存と共有へ拡張しています。

**ブラウザ → Cloudflare Workers → D1**

## 4. 実装

自身が仕様やデザインの方向性を決め、Codexに実装と検証を依頼しました。
サブエージェントによる作業分担も利用してみました。

文言の一部はEclipseで編集し、配色もAI感を減らすために自分で選定しています。

## 5. 修正・デバッグ

実際の表示やエラーを確認し、AIにみてもらい原因を切り分け修正しました。

## 6. 開発環境・環境操作

| 役割 | 使用技術 |
|---|---|
| 画面 | HTML・CSS・JavaScript |
| API・データ保存 | Cloudflare Workers・D1 |
| 開発・テスト | Node.js・SQLite・Wrangler |
| 管理・公開 | GitHub・Cloudflare Workers Builds |

## 7. コードの品質担保

正常動作に加え、不正な操作や保存失敗からデータを守ることを確認しました。

**確認観点：件数上限・状態遷移・履歴・権限・保存競合**

ローカルの自動テストと、公開環境の主要操作確認を実施しています。

## 8. AI活用で得られた知見

- **工程に合わせて指示方法を変える**  
  アイデア出し・要件定義は対話形式で進め、実装・修正・テストはMarkdownで整理して依頼しました。(別チャットにてプロンプト生成)

- **ゴールと変更範囲を明確にする** 
  目指す成果物、依頼内容、変更しない箇所、重視する条件を分けて伝えました。

- **必ず不明点有無を質問する**  
  判断が必要な点は、着手前に質問するよう指示しました。
  不明点や確定していない部分を無理に作り上げさせないことでより明確な作り込みを目指しました。

- **サブエージェントで役割を分ける**  
  実装・テストなどの担当を分け、テスト担当が確認する様子もリアルタイムで追えました。

- **場所に合わせて確認方法を変える**  
  自宅PCにスマートフォンから接続し、外出先では画像で成果物の反映箇所をaiに投げてもらい確認しながら進めました。

- **完了報告と実際の結果を照らし合わせる**  
  AIの報告に加え、画面やテスト結果、本番環境への反映を確認することを意識しました。

実装からテストまで一貫して依頼できることが利点でした。
一方、指示の抜けや意図しない変更を防ぐためのプロンプトについてはもっと学べることがあり改善できる点だとも思いました。
