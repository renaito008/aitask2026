# 1on1目標・タスク管理アプリ 使用マニュアル

作成日：2026-11-15  
ソースと過去の確認記録に基づく。今回、アプリの新規登録・操作検証は行っていない。

## 1. アプリを開く

[公開アプリ](https://task-management-api.renaito008.workers.dev/)

インストール・ログインは不要。公開トップは新しいルームを作る入口。
作成済みの目標を見る場合は、そのルームの編集リンクまたは閲覧リンクを使う。

| 種類 | 利用者 | 用途 |
|---|---|---|
| 編集リンク | 本人 | 登録・編集・保存・記録・条件付き削除・リンク再発行 |
| 閲覧リンク | 上司・1on1相手など | 保存済みの内容と履歴を見る |

編集リンクは本人だけで保管し、相手には閲覧リンクを渡す。
リンクを知る人にアクセスを許可する方式であり、社員アカウントによる本人確認ではない。

## 2. ルームを作る

1. 公開URLを開く。
2. メンバー名、1on1実施日、IT業界への入職年月を入力する。
3. 「ルームを作成」を押す。
4. 発行された編集リンク・閲覧リンクをそれぞれ控える。
5. 「編集画面を開く」から進む。

実施日は今日以前、入職年月は当月以前。入職年月より前の実施日は指定できない。
業界歴は自動計算される。

**保管するのは、作成時に発行された元のリンク。**
読み込み後は秘密部分がURLから取り除かれる。アドレス欄の「/room」だけを保存しても、別の端末で同じルームへアクセスするリンクにはならない。
編集画面を開ける場合は「共有リンクの管理」から編集リンクを表示できる。
メールやアカウントによる編集リンクの復旧機能はない。

## 3. 画面の見方

- 基本登録情報：名前・実施日・入職年月・業界歴。
- 現在の目標：取り組み中と達成済み、それぞれのタスク・進捗。
- 過去3回の1on1：記録した時点のコピー。閲覧のみ。
- 変更を保存：通常の変更をサーバーへ反映。
- 最新情報に更新：保存済みの最新データを取得。
- 今回の1on1を記録：保存済みの内容を履歴へ記録。
- 共有リンクの管理：編集権限だけで表示・再発行可能。

「未保存の変更あり」の内容は、まだ閲覧者へ反映されない。

## 4. 目標を登録・編集する

1. 「＋ 目標を追加」を押す。
2. 目標名と期限を入力し「確定」を押す。
3. 「変更を保存」を押し、成功表示を確認する。

取り組み中は最大3件。達成済みは別枠。目標名は空白のみ不可・最大100文字。
「目標を編集」で名前と期限を変更し、保存できる。
達成済みを変更したい場合は先に「取り組みを続ける」で再開する。

## 5. タスクを登録・編集・削除する

### 登録

1. 対象目標の「＋ タスクを追加」を押す。
2. タスク名、期限、優先度（低・中・高）を入力・選択する。
3. 「確定」して「変更を保存」を押す。

各目標で最大3件。完了タスクも件数に含まれる。タスク名は空白のみ不可・最大100文字。
過去の期限も指定でき、期限を過ぎた未完了には期限切れが表示される。

### 編集

タスクの「編集」から名前・期限・優先度を変更し、確定して保存する。
通常の完了タスクは編集できない。修正が必要なら、目標の継続・再開を選ぶ。

### 削除

未完了タスクの「削除」を押し、確認画面で承認した後に保存する。進捗は再計算される。
通常の完了タスクは削除できない。専用のゴミ箱はないため、削除前に確認する。

## 6. 完了・達成・継続

タスクにチェックを入れると進捗が変わり、最後のタスクでは確認画面が開く。

| 選択 | 動作 |
|---|---|
| 達成済みにする | 目標とタスクを達成済み欄へ移し、取り組み中の枠を空ける |
| まだ取り組む | 取り組み中に残し、完了タスクも再編集できるようにする |
| Escなどで閉じる | 取り組み中に残すが、完了タスクのロックは解除しない |

選択後は「変更を保存」で確定する。
完了した瞬間に自動削除されることはない。タスク0件は0%で、達成済みにできない。
確認を閉じた後も「達成を確認」から選択できる。

## 7. 取り組みを再開する

達成済み目標の「取り組みを続ける」を押し、確認後に保存する。
取り組み中の空き枠が必要。既存の完了状態は残るため、必要なタスクだけを未完了へ戻す。
取り組み中の100%目標も、継続操作で再編集できる。

## 8. 1on1を記録する

1. 基本情報の実施日を、その回の日付にする。
2. 目標・タスクを更新し「変更を保存」を押す。
3. 「今回の1on1を記録」を押す。
4. 「過去3回の1on1」で記録を確認する。

履歴には基本情報、全目標、全タスク、期限、優先度、完了状態、進捗を含む。
未保存なら先に保存するよう案内される。
同日は確認後に上書きする。以前のその回の内容は置き換わる。
実施日順に最新3回を保持し、4回目の記録で最も古い回が保持対象から外れる。
現在の編集は過去の履歴へ自動反映されない。
保持中の3回より古い実施日を、新しい回として追加できない。

## 9. 振り返った達成済み目標を削除する

1. 達成日より後の1on1で、その目標を振り返る。
2. 最新内容を保存し「今回の1on1を記録」を成功させる。
3. 「振り返り済み・削除」が有効になったことを確認する。
4. 押して確認し、現在の達成済み欄から削除する。

この操作はサーバーで成功した時点で確定する。
保存済み履歴には内容が残るが、履歴自体も最新3回の保持制限を受ける。
同日記録だけでは削除できない。記録後に再開・変更した場合、変更前の記録だけで削除できない。

取り組み中の「目標を削除」は別操作。現在のタスクもまとめて削除して保存する。
通常状態で完了タスクが含まれる場合は拒否される。保存済み履歴は変更しない。

## 10. 相手へ共有する

作成時に発行した閲覧リンクを相手へ渡す。相手はログインせず、現在の内容と履歴を見られる。
本人の保存後、相手側で「最新情報に更新」を押す。リアルタイム自動更新ではない。

- 編集・閲覧は別タブで開くと、役割切り替えの混乱を避けやすい。
- GitHubのURLはソースコード閲覧用であり、目標を見る共有リンクではない。
- 公開トップページの共有は、新しいルームを作る入口を共有することになる。
- 秘密リンクを資料、公開リポジトリ、画面共有のリンク表示欄へ載せない。

## 11. リンク再発行

編集画面の「共有リンクの管理」から、閲覧・編集・両方の対象を選ぶ。

1. 未保存の変更があれば先に保存する。
2. 対象の再発行ボタンを押す。
3. 旧リンクが使えなくなることを確認し、承認する。
4. 新しいリンクを控える。閲覧リンクなら相手へ渡し直す。

再発行は直ちにサーバーで確定し、通常の保存ボタンを待たない。
閲覧者は再発行できない。編集リンクを完全に失った場合の復旧機能はない。

## 12. 困ったとき

| 状況 | 対応 |
|---|---|
| 変更が相手に見えない | 本人の保存成功と、相手の「最新情報に更新」を確認 |
| 別の画面で更新されたと表示 | 入力を別途控え、最新情報を取得し、必要な変更をやり直す |
| 保存失敗 | 入力を保持し、接続を確認して再試行。閉じる前に入力を控える |
| 更新時に破棄確認 | 未保存の変更がある。入力を控えて破棄の可否を判断 |
| リンク無効・再発行済み | 正しい種類の最新リンクを確認。閲覧者は本人から受け取る |
| 完了タスクを編集できない | 継続・再開を選ぶ。確認を閉じただけではロック解除されない |
| 追加できない | 目標3件、各目標3タスクの上限を確認 |
| 達成済みを削除できない | 達成日より後の1on1に最新内容を記録したか確認 |
| ブックマークから開けない | /roomだけでなく、元の発行リンクを控えているか確認 |

## 13. 発表用デモ

架空ルームに目標1件・未完了タスク1件を事前に保存し、編集画面と閲覧画面を開く。
「完了→達成確認→保存→閲覧側更新」を約45秒で示す。
実データ、秘密リンク表示、削除、リンク再発行はデモへ含めない。
今回の文書作成ではデモデータの作成・操作はしていない。
