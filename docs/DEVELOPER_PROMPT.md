## 技術方針

- 初版の画面はHTML・CSS・JavaScriptを基本に、軽量で理解しやすい構成にしてください。
- 既存プロジェクトに適切な構成がある場合は尊重し、必要もなくフレームワークを入れ替えないでください。
- 新規プロジェクトで重いフレームワークや外部ライブラリを導入する場合は、必要性を説明してください。
- 保存処理はRepositoryとして分離し、画面からlocalStorageを直接呼び出さないでください。
- ローカル試作ではlocalStorageによる保存を許可します。データの復元、バージョン識別、不正データ・保存失敗時の対応を実装してください。
- 本番DB・公開先・サーバーフレームワークは今回確定しないでください。Node.jsとSQLiteは候補に留めます。
- ローカル起動方法をREADMEへ記載してください。

## デザイン・操作

- これはアプリであり、スライドではありません。
- 業務で使いやすく、少し懐かしさと温かみのあるUIにしてください。
- ドット絵は小さな装飾・アイコン・SVGなどで取り入れ、本文や入力欄の可読性を落とさないでください。
- 基本情報、取り組み中の目標、達成済みの目標、履歴を見つけやすく配置してください。
- メンバーは編集、上司は閲覧のみ。試作ではモードを切り替えて確認できるようにしてください。
- 本番の共有・権限が未実装であることをREADMEと試作画面に簡潔に明記してください。
- 主要な操作は少ないクリックで行い、入力内容と保存状態が分かるようにしてください。

## 仕様の厳守ポイント

- 取り組み中の目標3件、各目標の全タスク3件を上限とします。
- 完了タスクは通常編集不可。継続・再開した目標では再編集可能です。
- 100%達成は自動削除・移動しません。確認の承認後に達成済みへ移動します。
- 履歴は過去3回分。過去3ヶ月分ではありません。現在データとは独立したコピーです。
- 達成済み目標は次回1on1で記録・振り返り後、確認して削除します。
- IT業界歴は入職年月から計算します。
- サブタスク・AI機能・リアルタイム共同編集は追加しません。
